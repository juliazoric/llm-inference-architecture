# Архитектура инференса LLM

Расчёты и выводы по запуску больших MoE-моделей на нестандартном
железе: CPU-хосты, телефонные кластеры, дискретные GPU.

Целевая модель — **Qwen3.8-Flash-Next** (125B всего / 6B активных,
48 слоёв × 512 экспертов, гибрид Gated DeltaNet + QSA).

## Три главных вывода

**1. Всё решает соотношение GFLOPS / ГБ/с.**
```
CPU 7430U:  114 / 41  = 2.8 FLOP на байт → compute-bound
Arc B50:  15000 / 224 = 67  FLOP на байт → memory-bound
```
У CPU простаивает память, у GPU — вычисления. Все приёмы — попытка
занять простаивающее.

**2. MTP работает только на memory-bound части.**
На compute-bound он математически хуже в 1/α раз. Поэтому на CPU
он даёт 1.3-1.5×, а на GPU — 3-5×.

**3. Пайплайн по слоям не ускоряет один чат.**
Задержка = сумма, а не максимум. Использовать compute всех устройств
можно только через тензорный параллелизм — резать каждый слой.

## ⚠️ Статус

Все числа — **оценки по пропускной способности памяти и GFLOPS**,
не замеры. Реальный llama.cpp обычно даёт 60-80% от теоретического.

Что проверено на практике: ничего из этого не запускалось.
Чего не хватает для проверки: телефонный кластер, тензорный
параллелизм в llama.cpp (не существует), MTP для Qwen3.8
(поддержка не подтверждена).
